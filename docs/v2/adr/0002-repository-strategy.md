# ADR-0002 — 저장소 전략: 같은 repo의 main에서 v2를 진행한다

- 날짜: 2026-10-06
- 상태: 확정 (Jeffrey 비준)
- 관련: 핸드오프 §9-6

## 맥락

v1(`v0.1.1`)은 결함이 확인되어 아카이브하기로 했다. v2는 재구축한다(ADR-0001). 이에 따라 정해야 할 것은 세 가지다.
- v2를 어디서 개발할지
- 이름을 유지할지
- 버전 번호를 어떻게 매길지

2026-10-06 기준 `Di-Vernon/stare-decisis`의 상태는 다음과 같다.
- 별 1, fork 0, 열린 이슈 0, 릴리스 0
- 브랜치는 `main` 하나
- 태그는 `v0.1.0`, `v0.1.1`

## 선택지

- **(A) 같은 repo의 main에서 v2를 진행한다.** v1은 태그로 보존한다.
- **(B) 새 repo를 만든다.** Vue 3(`vuejs/core`), Yarn 2(`yarnpkg/berry`), Angular 2+(`angular/angular`)가 이 방식을 썼다. 구버전을 병행 유지보수해야 했기 때문이다.
- **(C) 같은 repo에 장기 `v2` 브랜치를 둔다.**

## 선택

**(A)**. 세부 사항은 다음과 같다.

1. v1 코드는 태그 `v0.1.1`(`0976882`)로 보존한다. 별도 브랜치는 만들지 않는다.
2. 설계 단계에서는 main에 v1 코드와 `docs/v2/`가 공존한다. README 첫머리에 v1이 아카이브 상태임을 명시한다.
3. 구현을 시작하는 시점에 v1 코드를 main에서 커밋 하나로 제거한다. 제거된 코드는 태그와 git 이력에 그대로 남는다.
4. 이름은 유지한다. repo·패키지는 `stare-decisis`, CLI는 `myth`다.
5. v2의 첫 릴리스 번호는 `0.2.0`이다. "v2"는 내부 설계 명칭으로만 쓴다.

## 근거

- (B)와 (C)를 택한 선례는 구버전 사용자를 병행 지원해야 하는 경우였다. 현재 v1에는 외부 사용자가 사실상 없으므로 이 이유가 성립하지 않는다.
- (B)를 택하면 이력, 링크, 별 수가 끊긴다.
- (C)를 택하면 방문자는 기본 브랜치에서 v1 코드를 보게 된다. 브랜치가 오래 갈수록 main과 차이도 벌어진다.
- 이름 `stare decisis`(선례 구속)는 v2의 정체성과 정확히 맞는다. v2는 사건을 모아 precedent로 만들고, codification ladder로 승격시키는 구조다.
- 아직 1.0 이전 단계이므로 SemVer상 `0.2.0`이 자연스럽다.
  - v1 이력의 커밋 메시지 하나(`6f58eb8`)가 "v0.2.0-alpha"를 언급한다. 하지만 이 이름으로 된 태그나 릴리스는 없으므로 충돌하지 않는다.

## 영향 범위

- `README.md` 첫머리에 아카이브 안내를 추가한다(이 커밋에 포함).
- `docs/12-DEPLOYMENT.md`의 `git checkout v0.2.0` 예시는 v1 문서이므로 손대지 않는다.
