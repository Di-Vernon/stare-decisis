# ADR-0009 — completion report 형식

- 날짜: 2026-10-06
- 상태: 확정 (Jeffrey 비준)
- 관련: audit 설계 D5

## 맥락

intent 오독은 audit으로 잡지 않는다(ADR-0006). 그러므로 사용자가 결과를 보고 빠르게 판단할 수 있어야 한다. Claude의 자유 형식 보고는 하지 못한 범위를 뒤에 묻어 두거나, 하지 않은 검증을 했다고 주장하는 일이 있다.

## 선택

Claude는 작업 턴을 마칠 때 아래 네 칸으로 보고한다. 작업 턴은 파일 변경이 있었거나 완료 claim을 한 턴이다.

- **Done**: 한 일
- **Verified**: 증거로 확인한 것. 명령과 결과를 함께 적는다(예: `npm test` exit 0).
- **Not done / Unverified**: 하지 않았거나 확인하지 못한 것
- **Assumptions**: 지시가 모호해서 Claude가 선택한 해석

audit은 보고의 의미를 판정하지 않는다. 결정적으로 두 가지만 본다.

1. 네 칸이 있는가 (ADR-0008 #2)
2. Verified에 적힌 실행이 실제 기록과 일치하는가 (ADR-0008 #1)

변경된 파일 목록은 Claude가 다시 쓰지 않고 change tree(ADR-0010)를 참조한다.

## 근거

- **하지 못한 범위를 먼저 드러내게 해야 한다.** OverclaimBench(arXiv 2609.20812, 초록 기준)에서 에이전트가 요청 파일을 다 읽지 않은 실행이 67.9%였고, 그중 80.4%가 오도적 보고였다. [B, 벤치마크]
- **Assumptions 칸은 intent 오독을 사용자가 빨리 알아채게 하는 장치다.** 의도 오독의 상당수는 명세의 빈칸을 그럴듯하지만 틀린 해석으로 채운 경우였다(Tang et al.). [B, 실사용]
- **"단계를 추가하라"는 prescribe형 지시는 텍스트 상기와 1회 피드백만으로 준수율이 77–100%까지 회복된다**(RepoComplianceBench, arXiv 2607.26819). 따라서 형식 누락은 피드백으로 교정할 수 있다. [A]

## 영향 범위

- 형식 안내는 SessionStart에 한 번 짧게 넣는다. 매 프롬프트 상시 주입은 하지 않는다.
- 질문·답변만 오간 턴에는 형식을 요구하지 않는다.
