# ADR-0007 — audit 단계 도입: M0에는 A0과 A1만

- 날짜: 2026-10-06
- 상태: 확정 (Jeffrey 비준)
- 관련: audit 설계 D3

## 맥락

audit의 완성형에는 intent contract 추출, scope 검사, LLM 2단계 판정, 실행 전 확인 질문까지 들어간다. 이 기능들은 LLM 호출과 오버헤드를 늘리지만, 효과는 실사용 기준으로 측정된 적이 없다.

## 선택

| 단계 | 내용 | LLM 호출 | 시점 |
|---|---|---|---|
| A0 | 결정적 검사(ADR-0008) | 0 | M0 |
| A1 | 라벨 수집과 정밀도 측정(ADR-0012) | 0 | M0 (A0과 동시) |
| A2 | intent contract, scope 검사, LLM 2단계 판정, 실행 전 확인 질문 | 필요할 때만 | A1 데이터가 필요성을 보일 때 |

- A2에서도 intent contract는 매 프롬프트가 아니라 audit이 필요할 때만 추출한다.
- M0에서는 프롬프트에 명시된 경로·파일명만 결정적으로 기록해 둔다(LLM 호출 없음).

## 근거

- 측정된 병목만 최적화한다(불변 원칙).
- 단일 LLM judge의 거짓 완료 판정은 AUROC 0.54–0.65다. 반면 경량 trajectory 검출기는 0.83/0.95다(arXiv 2606.09863, 벤치마크, 초록 기준). LLM 단계를 먼저 넣을 근거가 약하다.
- 벤치마크로만 보정한 verifier는 실사용에서 무작위 수준이었다(OpenHands critic, AUC 0.45–0.48). 따라서 실사용 라벨(A1)이 먼저 필요하다. [B]
- v1의 근본 원인 중 하나는 "피드백 루프 하나 없이 복잡도부터 쌓았다"였다.

## 영향 범위

- M0의 최소 루프(교정 감지 → case file → holding → ratification → L2 경고 → 재발률 계측)에 A0·A1을 병행한다.
- LLM 판정 경로와 과금 문제(핸드오프 §9-4)는 A2 진입 시점에 함께 결정한다.
