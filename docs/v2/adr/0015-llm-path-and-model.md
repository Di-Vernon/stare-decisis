# ADR-0015 — LLM 사용: 승격 제안 시 holding 초안만, 세션 모델에 fork로 맡긴다

- 날짜: 2026-10-07
- 상태: 확정 (Jeffrey 비준)
- 관련: 핸드오프 §9-4, ADR-0005, ADR-0013

## 맥락

새 모델은 계속 나온다. myth가 특정 모델을 지정하고 그 성능에 의존하면, 모델이 바뀔 때마다 동작도 함께 바뀐다. 그래서 두 가지를 먼저 물었다.

1. myth에서 모델 성능이 정말 중요한가.
2. 정교한 휴리스틱을 만들고, 모델은 꼭 필요한 곳에만 쓸 수 있는가.

## 분석

| 작업 | 빈도 | 처리 방식 |
|---|---|---|
| 교정 후보 감지 | 매 턴 | 결정적 신호: interrupt, 권한 거절, 같은 파일 재수정, 어휘 패턴 |
| precedent 적용 판단(L2) | 매 tool call | 결정적 matcher: 경로 glob, 명령 패턴, 도구 |
| counters, 재발률, 강등 | 상시 | 계산 |
| audit A0 | 매 Stop | 결정적 검사(ADR-0008) |
| 패턴 분석 | 주기적 | 구조 사실 기준 군집 |
| **holding / matcher 초안** | **드묾** | **언어 이해가 필요하다. 다만 필요한 것은 성능보다 맥락이다.** 예: "아니 그거 말고"를 규칙으로 만들려면 직전 상황을 알아야 한다 |

- 빈도가 높은 경로는 모두 결정적으로 처리할 수 있다.
- 강한 모델도 이런 판정에는 약했다.
  - coding-agent 교정 판정 정확도는 최고 0.74였다(SWE-chat, R1).
  - 거짓 완료 판정은 AUROC 0.54–0.65였다(R2).
  - auto mode classifier는 Sonnet을 쓰고도 FNR이 17%였다(R2).
- 결정적 경로는 재현할 수 있고, 모델이 교체돼도 유지된다. "수렴은 법"이라는 대원칙과도 맞는다.

## 선택

### 1. LLM 사용처는 한 곳

- 교정 후보는 조용히 case file로만 쌓는다. 이 단계에는 LLM 호출도, 사용자 질문도 없다.
- 같은 패턴이 반복돼 **승격을 제안하는 순간에만** LLM으로 holding과 matcher 초안을 만든다.
  - 같은 패턴인지는 결정적으로 판단한다. 기준은 "Claude가 무엇을 했는가"의 구조 사실(도구, 경로, 명령)이다.
  - 승격 기준은 핸드오프 L0→L1 조건을 따른다.
- 결과적으로 호출 빈도는 "새 precedent가 생길 때 1회"가 된다.
- 후보 단계의 `classify` 추가 여부는 E2에서 결정적 감지의 재현율을 측정한 뒤 정한다.

### 2. 모델은 지정하지 않는다: `$.model.fork`

- 초안 작성은 `$.model.fork`로 세션 모델에 맡긴다.
  - fork는 세션 transcript와 prompt cache를 공유한다. 그래서 맥락을 갖고 있고, 비용이 낮다.
  - 사용자가 쓰는 최신 모델을 자동으로 따라간다.
- myth 코드에는 모델 ID나 별칭을 하드코딩하지 않는다. 이 원칙이 v1의 Model Separation Rule(Reflector Haiku / Curator Sonnet)을 대체한다.
- reasoning-blind 원칙(ADR-0005, R2)은 **판정**(audit)에만 적용한다. 초안 작성은 판정이 아니다.
- 작업자 자신이 규칙을 약하게 쓸 위험은 두 장치로 막는다.
  - **원문 인용 의무**: 초안에 사용자 원문의 정확한 인용(evidence span)이 없거나, 인용이 원문과 일치하지 않으면 그 초안은 무효다. tellonce에서 차용한 신뢰 경계다(ADR-0001).
  - **ratification**: 사용자가 확정한다.
- fork가 null을 반환하면(cold snapshot, API 오류) 제안을 보류하고, 다음 턴이 끝난 뒤 다시 시도한다. 후보는 파일 큐에 남는다.

### 3. 호출 시점

- 사용자 작업을 막지 않는다. 승격 제안은 턴이 끝난 뒤 백그라운드에서 준비한다.
- 제안을 사용자에게 보여 주는 횟수는 intervention budget(ADR-0012)을 따른다.

### 4. 예산과 고지

- **구독 사용자**: `$.session.usage().rateLimits`의 사용률이 기준값 이상이면 LLM 작업을 미루고 큐를 유지한다.
- **API key 사용자**: `rateLimits`가 비어 있으므로 일일 비용 상한으로 판단한다.
- 세션당 호출 상한을 둔다.
- 위 기준값은 모두 설정값이다. 근거 있는 수치가 없으므로 초기값은 spike S1의 실측을 보고 정한다.
- README와 첫 실행 안내에 "myth는 사용자의 plan 또는 API key 사용량을 소모한다"고 명시한다. `/myth status`에는 myth의 추정 사용량을 보여 준다(`complete`가 사용량을 반환하지 않으므로 글자 수로 추정한다).
- 호출은 세션과 같은 제공자로 간다. 제3자에게 데이터를 보내는 경로는 없다.

## 기각: zero-LLM 모드

holding을 사용자가 직접 다듬어야 하는 모드는 두지 않는다. 그 정도 수고를 들일 사용자라면 매 작업 결과를 직접 대조할 것이다. 그렇다면 myth의 효용이 없다.

## 한계

- 결정적 교정 감지의 재현율은 근거가 없다. 일반 대화 연구에서 키워드 방식의 재현율은 1%였고, 한국어 근거는 없다. E2에서 측정한다.
- fork는 세션의 메인 모델을 쓴다. 따라서 호출 1회당 비용은 small model보다 클 수 있다. 다만 호출이 드물고 캐시를 공유하므로, 실제 영향은 spike S1에서 측정한다.
