# ADR-0017 — completion report의 고정 형식: claim을 구조적으로 파싱한다

- 날짜: 2026-10-07
- 상태: 확정 (Jeffrey 비준)
- 관련: ADR-0009 보완, ADR-0008의 claim 감지 방식 대체, ADR-0016

## 맥락

ADR-0008은 claim 감지를 한·영 결정적 문장 패턴으로 하기로 했다. 그러나 ADR-0016으로 어휘 사전을 쓰지 않기로 했다. 또 Claude는 사용자 언어로 응답하므로, 문장 패턴으로 claim을 감지하면 언어마다 패턴을 따로 만들어야 한다.

## 선택

completion report(ADR-0009)의 형식을 고정한다. 칸 제목은 영어로 고정하고, Verified 칸은 기계가 읽을 수 있는 형식으로 쓴다. 나머지 칸의 서술은 사용자 언어로 쓴다.

```
## Done
- (사용자 언어로 서술)

## Verified
- `npm test` → exit 0
- `tsc --noEmit` → exit 0

## Not done / Unverified
- (사용자 언어로 서술)

## Assumptions
- (사용자 언어로 서술)
```

### Verified 칸 규칙

- 한 줄에 검증 하나를 쓴다. 형식은 `` `명령` → exit N ``이고, 뒤에 짧은 설명을 붙일 수 있다.
- 명령 실행으로 확인한 것만 Verified에 쓴다. 명령으로 확인할 수 없는 것은 Done이나 Not done / Unverified에 쓴다.

### audit이 결정적으로 검사하는 것

1. 칸 제목 4개가 있는가 (ADR-0008 #2).
2. Verified의 각 줄에 대해, 같은 턴에 실행된 Bash 기록에 그 명령이 있는가.
   - 비교는 앞뒤 공백 등 정규화한 문자열로 한다.
   - 기록된 exit code가 보고한 값과 같은가 (ADR-0008 #1).
3. 명령이 기록에 없으면 "실행 없는 검증 주장"으로 피드백한다. exit code가 다르면 사실 모순으로 피드백한다.

## 근거

- 고정 형식이면 claim 감지가 언어와 무관해진다. 언어별 사전이 필요 없다.
- 하지 못한 범위와 검증되지 않은 범위를 따로 드러내게 하는 것은 과장 보고에 대한 처방이다(OverclaimBench, arXiv 2609.20812, 초록 기준).
- "단계를 추가하라"는 지시는 상기와 1회 피드백만으로 준수율이 77–100%까지 회복되었다(RepoComplianceBench, arXiv 2607.26819). 따라서 형식 누락은 피드백으로 교정할 수 있다고 본다.

## 영향 범위

- ADR-0008의 "claim 감지: 한·영 결정적 패턴" 항목은 이 ADR로 대체된다.
- 형식 안내는 SessionStart에서 한 번 짧게 주입한다(ADR-0009).
- Claude가 형식을 얼마나 지키는지는 A1 데이터로 관찰한다.
