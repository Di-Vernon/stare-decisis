# ADR-0008 — A0 결정적 검사 목록

- 날짜: 2026-10-06
- 상태: 확정 (Jeffrey 비준)
- 관련: audit 설계 D4

## 선택

| # | 검사 | M0 개입 수준 |
|---|---|---|
| 1 | claim과 증거의 사실 모순. 예: "테스트 통과" claim이 있는데 마지막 테스트 exit code가 0이 아님 | 턴당 1회 피드백(Stop `additionalContext`) |
| 2 | completion report 형식 누락. 작업 턴에 한함(ADR-0009) | 턴당 1회 피드백 |
| 3 | 완료 claim이 있는데 해당 턴에 테스트 실행이 0회 | shadow mode |
| 4 | 피드백 직후 테스트 파일 변경 | shadow mode. gaming 의심으로 기록 |
| 5 | 같은 파일 반복 수정, 같은 시도 3회 이상(기존 evidence sensor) | 맥락 정보로만 사용. 단독 개입 없음 |

### 운영 규칙

- **#3을 shadow mode로 두는 이유**: 테스트가 없는 저장소나 비코드 작업에서 오탐이 나기 쉽다. A1 라벨로 정밀도가 확인되면 개입 수준을 올린다.
- **claim 감지**: 한·영 결정적 패턴을 쓴다. 패턴의 정밀도는 근거가 없으므로 E2(교정 감지 평가셋)에 claim 패턴을 함께 넣는다.
- **피드백 사유 형식**: 사실과 증거 위치만 적는다. 명세상 불가능하면 BLOCKED-IMPOSSIBLE과 근거를 보고해도 된다는 출구를 함께 준다. 테스트 기댓값이나 "통과시켜라" 같은 목표는 넘기지 않는다.
- **표현 방식**: 명령조가 아니라 사실 진술로 쓴다.
- **루프 방지**: `stop_hook_active=true`이면 피드백을 생략한다. 상한은 myth 자체 카운터로 강제한다.

## 근거

- **사실 모순은 transcript 밖의 해석 없이 확인되는 사실이다.** 거짓 완료(부정확한 자기 보고)는 실사용 오정렬의 22.58%를 차지한다(Tang et al., arXiv 2605.29442). [B, 실사용]
- **피드백을 반복하면 부정행위가 늘 수 있다.** ImpossibleBench(arXiv 2510.20270)에서 피드백과 함께 여러 번 제출하게 하자 평균 부정행위율이 33%에서 38%로 올랐다(2차 인용). [B]
- **출구는 일부 모델에서 효과가 있다.** abort 출구로 GPT-5의 부정행위가 54%에서 9%로 줄었다(Conflicting-SWEbench). 다만 저자 글에 따르면 Claude Opus 4.1은 출구를 거의 쓰지 않았다. 따라서 myth 환경에서 출구 효과를 따로 측정한다(E-A4). [B]
- **명령조 additionalContext는 Claude의 prompt-injection 방어를 유발할 수 있다**(Claude Code 공식 문서). [B, 벤더]

## 영향 범위

- Stop command hook 하나가 #1–#4를 수행한다. LLM 호출은 없다.
- 피드백 상한 초기값은 턴당 1회, 세션당 3회다. 설정할 수 있고, 근거가 없으므로 E-A4에서 보정한다. 플랫폼 Stop 상한(연속 8회)보다 항상 낮게 유지한다.
