# ADR-0016 — 감지는 행동 신호로만 한다: 초기 버전에 어휘 사전 없음

- 날짜: 2026-10-07
- 상태: 확정 (Jeffrey 비준)
- 관련: 핸드오프 §9-7 (E2), ADR-0015

## 맥락

R1과 핸드오프는 교정 감지를 "한·영 어휘 패턴 + 행동 신호"로 하고, 한국어 성능은 E2에서 검증하는 하이브리드 방식으로 계획했다. 그러나 이후 결정 두 가지로 전제가 바뀌었다.

- 언어 이해는 모델이 맡는다. holding 초안은 `fork`로 세션 모델이 작성한다(ADR-0015).
- 후보는 조용히 쌓이고, 반복과 ratification을 거쳐야 승격된다. 그래서 감지기의 정밀도보다 재현율이 중요하다.

또 다음 사실을 확인했다.

- Claude 모델은 프롬프트를 영어로 번역한 뒤 작업하지 않는다. 내부 표현은 상당 부분 언어와 무관한 개념으로 처리되지만, myth는 그 표현에 접근할 수 없다. 모델의 언어 이해는 모델 제공자의 영역이다.
- 공개된 한국어 coding-agent 교정 데이터는 없다.

거짓 완료의 빈도는 다음과 같다.

- 개발자 반발로 드러난 오정렬 16,118건 중 부정확한 자기 보고가 22.58%다(CLI 26.66%, Tang et al., arXiv 2605.29442) [B, 실사용]. 해당 데이터의 SWE-chat 응답 중 94.9%가 Claude 계열이다.
- 이를 세션당으로 환산하면 약 0.18건이다. 사용자가 지적한 것만 센 하한선이다 [D, 계산].
- 불가능 과제에서 Claude의 테스트 조작률은 45–50%이고, 그중 79% 이상이 테스트 파일 수정이었다(ImpossibleBench, arXiv 2510.20270) [B, 벤치마크].

## 선택

초기 버전은 **모든 언어에서 어휘 사전 없이 행동 신호만** 쓴다. 한국어만 빼면 언어별로 동작이 달라지므로 영어 사전도 함께 뺀다.

| 신호 | 대상 |
|---|---|
| audit A0: claim과 증거 대조 (ADR-0008, ADR-0017) | 거짓 완료 |
| 사용자가 붙여 넣은 오류 출력·스택 트레이스 (구조 패턴) | 거짓 완료, 실패 보고 |
| 완료 claim 직후 같은 파일 재수정, 같은 테스트 재실행 (rework) | 거짓 완료 |
| 사용자 턴 직후, 직전 행동을 같은 도구·같은 대상에 다른 인자로 다시 함 (redo) | 말로 한 교정 |
| 되돌리기 (`git restore`/`checkout`/`revert`, 직전 변경 원복) | 교정, 거부 |
| interrupt, 권한 거절 | 거부 |

## 근거

- 거짓 완료가 드러나는 경로는 대부분 언어와 무관하다. 사용자가 실패를 보고하거나, 다음 턴에 실제로는 다르다는 것이 드러난다(Tang et al.). 오류 출력은 사용자가 쓰는 언어와 관계없이 코드 위주로 붙는다.
- 사전이 있어야만 잡히는 경우는 하나다. 사용자가 말로만 실패를 알리고 아무 행동 신호도 남지 않는 경우다. 이 비율은 근거가 없다.

## 감수하는 비용

- 행동 신호는 정상적인 반복 개발과도 겹친다. 따라서 후보의 정밀도가 낮다. 후보가 조용히 쌓이고, 승격에는 반복과 ratification이 필요하므로 이 비용은 감당할 수 있다.
- 말로만 드러난 교정은 놓친다.

## E2 재정의

E2는 **E2a 하나**로 줄인다.

- SWE-chat 영어 데이터에서 반발이 있었던 턴 가운데, 위 행동 신호가 하나도 없는 비율을 측정한다. 이 값이 "사전을 뺀 비용"의 추정치다.
- 행동 신호는 언어와 무관하므로, 이 추정치는 한국어에도 대부분 그대로 적용된다.
- 이 비율이 크게 측정되면 그때 어휘 사전을 **모든 언어에 함께** 추가한다.
- 언어별 동작 차이가 없으므로 한국어 "미측정" 표기는 두지 않는다.
- SWE-chat 접근(Hugging Face 이용 조건 동의, read 토큰)은 구현 단계에서 한다.
